# mulle-craft Library Documentation for AI
<!-- Keywords: build, craft, dependency, orchestration, mulle-sde, shell, kitchen -->
## 1. Introduction & Purpose

`mulle-craft` is a **shell-script based build orchestration tool** that is a
core part of the `mulle-sde` commandline IDE. It "crafts" (builds and installs)
two things:

* your *project*, using `mulle-make`
* the *dependencies* of your project, as specified by a *craftorder* file
  (which can be generated by `mulle-sourcetree`).

`mulle-craft` is deliberately **unaware of the actual build tool** (cmake,
xcodebuild, ...); that is decided by `mulle-make`, which `mulle-craft` invokes.
It also invokes `mulle-dispense` to install crafted dependency products into a
`dependency` folder.

Conceptually it is a shortcut for a nested loop: for each project in the
craftorder, for each SDK, platform, and configuration triple, call
`mulle-make install` and `mulle-dispense`.

Key features:
* Multi-SDK / multi-platform / multi-configuration building.
* *Dispense styles* (`none`, `auto`, `relax`, `strict`, `tight`) that control
  how build products are laid out inside the `dependency` directory to avoid
  configuration clobbering.
* *Craftinfo* / definition-folder resolution: `mulle-craft` finds platform- and
  SDK-specific definition directories and forwards them to `mulle-make`.
* Marks in the craftorder that determine *how* each dependency is crafted
  (e.g. `no-craft-configuration-<c>`, `no-static-link`).
* Kitchen directory management, donefiles (remembering completed builds),
  status tracking, searchpath emission, and timestamped build logs.

## 2. Key Concepts & Design Philosophy

* **Command-line driven.** Unlike C libraries, the public "API" of `mulle-craft`
  is its **CLI subcommands** plus the **environment variables** it reads. Most
  behaviour is not controlled by command-line arguments but by environment
  variables (e.g. `MULLE_CRAFT_PLATFORMS`, `MULLE_CRAFT_SDKS`,
  `MULLE_CRAFT_CONFIGURATIONS`, `MULLE_CRAFT_DISPENSE_STYLE`, `KITCHEN_DIR`,
  `DEPENDENCY_DIR`, `ADDICTION_DIR`).
* **Kitchen, Dependency, Addiction.** `mulle-craft` distinguishes three
  directories:
  - `KITCHEN_DIR` — intermediate/during-build products (per-builder scratch).
  - `DEPENDENCY_DIR` — final installed dependency products ("like a `/usr`").
  - `ADDICTION_DIR` — optional place to get dependencies from.
* **Qualifier.** A `qualifier` string encodes the `sdk-platform-configuration`
  triple; it is passed to `mulle-sourcetree walk --qualifier` to filter the
  craftorder tree.
* **Dispense styles** fold or keep the SDK/PLATFORM/CONFIGURATION folders when
  placing products into `dependency`. `auto` (the default) keeps `Debug` but
  folds a `Release` configuration, SDK `Default`, and the host platform into
  the root.
* **Craftinfo search order.** For each to-be-built project, `mulle-craft`
  first searches `dependency/share/mulle-craft/<project>` for a matching
  *craftinfo* folder, preferring a platform-suffixed (`-<platform>`) folder
  over a plain one. If no info folder is found there, it falls back to a
  project-local `.mulle/etc/craft` or `.mulle/share/craft` folder.
* **Timestamped logs.** Each craft run stores build logs in a timestamped
  subdirectory so previous runs are preserved and never mixed with the current
  one.
* **Donefiles.** Files that remember which dependencies were built completely,
  used to skip re-building already-completed dependencies.

## 3. Core API & Data Structures

There are no C headers; the API surface is the `mulle-craft` executable, the
library shell scripts it loads from `src/`, and the environment variables.

### 3.1. `mulle-craft` (main executable)

Entry point dispatcher. Global flags (processed before the command):

| Flag | Purpose |
|------|---------|
| `--craftorder-file <file>` | specify craftorder file |
| `--definition-dir <dir>` / `--aux-definition-dir <dir>` | add a definitions directory |
| `--kitchen-dir <dir>` / `--build-dir <dir>` | specify kitchen directory |
| `--platform <platform>` | override `MULLE_CRAFT_PLATFORMS` |
| `--sdk <sdk>` | override `MULLE_CRAFT_SDKS` |
| `--configuration <c>` | override `MULLE_CRAFT_CONFIGURATIONS` |
| `--project-dir <dir>` | change project directory (`cd`) |
| `--dependency-dir <dir>` | specify dependency directory |
| `--force` | set `MULLE_FLAG_MAGNUM_FORCE` |
| `--no-craftorder-file` | set `CRAFTORDER_FILE=NONE` |
| `--craftorder-kitchen-dir <dir>` | set `CRAFTORDER_KITCHEN_DIR` |
| `--test-environment` | set `MULLE_TEST_ENVIRONMENT` |
| `--motd` / `--no-motd` | control message-of-the-day |
| `--` | pass remaining arguments to `mulle-make` |
| `-n`, `-s`, `-v`, `--version` | dry-run / silent / verbose / version |

Environment read by setup:
`MULLE_VIRTUAL_ROOT`, `MULLE_VIRTUAL_ROOT_ID`, `DEPENDENCY_DIR`,
`ADDICTION_DIR`, `KITCHEN_DIR`/`BUILD_DIR`, `CRAFTORDER_KITCHEN_DIR`,
`MULLE_MAKE`, `MULLE_DISPENSE`.

Version constants: `MULLE_EXECUTABLE_VERSION` (e.g. `4.1.0`).

### 3.2. Commands

The primary public API. Each command loads one of the `src/mulle-craft-*.sh`
modules and calls its `main`.

#### `craftorder` *(src/mulle-craft-build.sh, `craft::build::craftorder_main`)*
Build everything listed in a craftorder file, in dependency order.

Options: `--all` (rebuild everything), `--debug`, `--lenient`, `--mulle-test`,
`--no-hook`, `--no-protect`, `--release`, `--serial`, `--platform <p>`,
`--sdk <sdk>`, `--style <s>`, `--target <t>`, `--` (pass to mulle-make).

Marks understood in craftorder (from README): `no-craft-configuration-<c>`,
`no-craft-os-<os>`, `no-craft-platform-<os>`, `no-craft-sdk-<sdk>`,
`no-dependency`, `no-dynamic-link`, `no-inplace`, `no-mainproject`,
`no-memo`, `no-require-configuration-<c>`, `no-require-os-<os>`,
`no-require-platform-<os>`, `no-require-sdk-<sdk>`, `no-require`,
`no-rootheader`, `no-static-link`, `only-liftheaders`, `only-standalone`,
`version-max-<version>`, `version-min-<version>`.

#### `project` *(default; `craft::build::project_main`)*
Craft the main project in the current directory *without* a craftorder.
Same options as `craftorder`. A trailing positional command that is not a known
subcommand dispatches to `craft::build::single_dependency_main`, i.e. builds a
single named dependency.

#### `clean` *(src/mulle-craft-clean.sh, `craft::clean::main`)*
Remove craft products. By default removes `KITCHEN_DIR`. Named targets:
`all`, `craftorder`, `dependency`, `dependency-store`, `project`.
Options: `--touch`, `--platform <p>`, `--configuration <c>`, `--sdk <s>`.
Env: `KITCHEN_DIR`, `DEPENDENCY_DIR`.

#### `list` *(src/mulle-craft-build.sh, `craft::build::list_craftorder_main`)*
List the remaining (not-yet-built) builds in the craftorder file.

#### `status` *(src/mulle-craft-status.sh, `craft::status::main`)*
Show craft status of project dependencies (without subprojects). Returns 0 if
the dependency is ready. Options: `--output-no-color`, `-f <craftorder>`
(required). Depends on `CRAFTORDER_FILE`.

#### `quickstatus` *(src/mulle-craft-dependency.sh, `craft::dependency::quickstatus_main`)*
Fast dependency readiness check.

#### `log` *(src/mulle-craft-log.sh, `craft::log::main`)*
Inspect kitchen logs. Shows a step table of the most recent craft run by
default. Projects/globs select logs (`*` = all, `''` = main only). Commands:
`<n>` (step output), `diff`, `errors`, `list`, `runs`, `status`, `warnings`,
or any tool (`cat`, `grep`, ...). Options: `--all`, `--raw`,
`-c <configuration>`, `-t <tool>`, `--run <selector>`.

#### `donefile` / `donefiles` *(src/mulle-craft-donefile.sh, `craft::donefile::main`)*
Show contents/location of "donefiles" (records of fully-built dependencies).
Commands: `cat`, `list` (default). Options: `--configuration <c>`,
`--no-cat`, `--no-local`, `--no-shared`, `--platform <p>`, `--sdk <sdk>`.

#### `find` *(src/mulle-craft-craftinfo.sh, `craft::craftinfo::main`)*
Search for a craftinfo item (file or directory) in a project or in the
dependency `share/mulle-craft` folder. Options: `--project-dir <dir>`,
`--dependency-dir <dir>`, `--item <name>` (default `definition`),
`--no-platform`, `--no-local`. Env: `DEPENDENCY_DIR`.

#### `qualifier` *(src/mulle-craft-qualifier.sh, `craft::qualifier::main`)*
Print the craftorder qualifier, or match it against marks.
Command: `print` (default) or `match` with a list of marks.
Options: `--configuration <name>`, `--debug`, `--platform <name>`,
`--release`, `--sdk <name>`, `--no-lf`.

#### `style` *(src/mulle-craft-style.sh, `craft::style::main`)*
Show dispense subfolder(s) used for a given triple, or list known styles.
Commands: `show`, `list`. Styles: `none`, `auto`, `relax`, `strict`, `tight`,
and `i-<style>` (reverse order). Options: `--style <s>`, `--sdk <sdk>`,
`--platform <p>`, `--configuration <c>`. Env: `MULLE_CRAFT_PLATFORMS`.

#### `searchpath` *(src/mulle-craft-searchpath.sh, `craft::searchpath::main`)*
Emit a colon-separated searchpath for libraries, headers, frameworks, binaries
or the kitchen, from local dependencies and addictions (not system paths).
Types: `framework`, `header`, `library`, `binary`, `kitchen`.
Options: `--if-exists`, `--no-addiction`, `--platform <name>`, `--style <style>`,
`--release`, `--debug`, `--test`. Env: `ADDICTION_DIR`, `DEPENDENCY_DIR`,
`MULLE_CRAFT_DISPENSE_STYLE`.

#### `dependency` *(src/mulle-craft-dependency.sh, `craft::dependency::main`)*
Manage the dependency directory (useful in scripts that add files).
Command: `update`. Env: `DEPENDENCY_DIR`, `MULLE_CRAFT_DISPENSE_STYLE`.

#### `craftorder-kitchen-dir` *(src/mulle-craft-path.sh, `craft::path::main`)*
Print the build directory for a given project in the craftorder.
Options: `--configuration <c>`, `--debug`, `--if-exists`, `--platform <p>`,
`--release`, `--sdk <s>`, `--style <s>`.

#### Directory-query commands
`kitchen-dir`, `dependency-dir`, `addiction-dir` — compute and print the
qualified directory for a `configuration`/`sdk`/`platform`/`style`.
`libexec-dir` — print `MULLE_CRAFT_LIBEXEC_DIR` (the `src/` or `../libexec`
library location shown by `src/mulle-craft-path.sh` functions).

#### `tool-env` *(inline in the main script)*
Print the resolved raw environment values: `ADDICTION_DIR`,
`CRAFTORDER_KITCHEN_DIR`, `DEPENDENCY_DIR`, `KITCHEN_DIR`,
`MULLE_CRAFT_DEPENDENCY_UNQUALIFIED_DIR`, `MULLE_CRAFT_DEPENDENCY_QUALIFIED_DIR`,
`MULLE_CRAFT_SDK`, `MULLE_CRAFT_PLATFORM`, `MULLE_CRAFT_CONFIGURATION`,
`MULLE_CRAFT_DISPENSE_STYLE`.

#### `uname`, `version`
Print `$MULLE_UNAME` and `$MULLE_EXECUTABLE_VERSION`.

### 3.3. Library modules (`src/*.sh`)

Loaded lazily per command. Each defines a shooter-bomb guard
(e.g. `MULLE_CRAFT_BUILD_SH='included'`) and functions namespaced with
`craft::<area>::`:
- `mulle-craft-build.sh` — main craft logic (`craft::build::*`).
- `mulle-craft-clean.sh` — `craft::clean::*`.
- `mulle-craft-craftinfo.sh` — `craft::craftinfo::*` (definition/craftinfo search).
- `mulle-craft-dependency.sh` — `craft::dependency::*`.
- `mulle-craft-donefile.sh` — `craft::donefile::*`.
- `mulle-craft-log.sh` — `craft::log::*` (timestamped log handling).
- `mulle-craft-path.sh` — `craft::path::*` (directory computation).
- `mulle-craft-qualifier.sh` — `craft::qualifier::*`.
- `mulle-craft-searchpath.sh` — `craft::searchpath::*`.
- `mulle-craft-status.sh` — `craft::status::*`.
- `mulle-craft-style.sh` — `craft::style::*`.

## 4. Performance Characteristics

* **Process-launch heavy.** `mulle-craft` is a shell script that shells out to
  `mulle-make`, `mulle-dispense`, and `mulle-sourcetree`. Each project craft is
  a subprocess, so large craftorders are dominated by process and build
  overhead, not by `mulle-craft` itself.
* **Donefiles / memoization** make incremental builds fast: already-built
  dependencies are skipped, so repeated runs are near no-ops for unchanged
  craftorders.
* `--serial` builds sequentially; without it, builds may run in parallel
  (subject to `mulle-make`/`make` parallelism).
* **Not thread-safe by itself**: the tool is a commandline executor; users are
  told not to run multiple `mulle-sde`/`mulle-craft` commands in parallel.
* Searchpath/qualifier/style helpers are O(number of folders) string operations
  and are effectively O(1).

## 5. AI Usage Recommendations & Patterns

* **The public contract is the CLI + environment variables.** To "call the
  API" of `mulle-craft`, prefer invoking `mulle-craft <command>` with flags and
  env vars rather than sourcing `src/*.sh` internals directly (functions are
  namespaced and guarded but not a stable public API).
* **Set the environment, not just flags.** Configuration of what to build is
  driven by `MULLE_CRAFT_SDKS`, `MULLE_CRAFT_PLATFORMS`,
  `MULLE_CRAFT_CONFIGURATIONS`, `MULLE_CRAFT_DISPENSE_STYLE`, `KITCHEN_DIR`,
  `DEPENDENCY_DIR`, `ADDICTION_DIR`.
* **`--` passes trailing arguments straight to `mulle-make`** — use it for
  make-specific options.
* **Use `qualifier print` output with `mulle-sourcetree walk --qualifier`** to
  filter a craftorder consistently with what `mulle-craft` will actually build:
  `MULLE_CRAFT_QUALIFIER="$(mulle-craft qualifier --no-lf print)"`.
* **Use `searchpath <type>` in build scripts** to obtain include/lib/bin
  searchpaths for dependencies; `Release` is always a fallback for `Debug`.
* **Inspect logs without rebuilding** via `mulle-craft log` (step table),
  `mulle-craft log errors`, `mulle-craft log warnings`, and `--raw` for the
  full dump.
* **Remember `donefile list`** to see which dependencies are already built.
* **Avoid running multiple craft commands in parallel** (mulle-sde convention).

## 6. Integration Examples

### Example 1: Crafting the project (default command)

```sh
# Build the main project in the current directory using mulle-make.
# Release configuration, host platform, Default SDK, auto dispense style.
mulle-craft project --release
```

### Example 2: Building dependencies from a craftorder, then the project

```sh
# Build all dependencies in dependency order, Debug only, then the project.
mulle-craft craftorder --debug

# Pass extra flags to mulle-make (everything after --).
mulle-craft craftorder --debug -- -j 4
```

### Example 3: Multi-SDK / multi-platform build status

```sh
# Cross-compile for two platforms, Release.
mulle-craft --platform linux --platform darwin --configuration Release craftorder

# Is a dependency ready? (status returns 0 if ready)
if mulle-craft status -f craftorder >/dev/null 2>&1
then
   echo "dependencies up-to-date"
fi
```

### Example 4: Feeding the qualifier to mulle-sourcetree

```sh
# Build a qualifier string and use it to walk/filter the craftorder exactly
# as mulle-craft would.
qualifier="$(mulle-craft qualifier --no-lf --platform linux print)"

mulle-sourcetree walk --qualifier "${qualifier}" \
   'printf "%s\n" "${WALK_INDENT}${NODE_ADDRESS} ${NODE_MARKS}"'
```

### Example 5: Emitting a header searchpath in a build script

```sh
# Produce include search paths for the local dependencies and addictions.
INCLUDE_PATH="$(mulle-craft searchpath header --style auto)"

# "library" gives -L style lib searchpaths; "binary" gives bin paths.
LIBRARY_PATH="$(mulle-craft searchpath library --style auto)"
```

### Example 6: Diagnosing a failed build from logs

```sh
# Latest run step table (stable step numbers):
mulle-craft log

# Full output of step 9:
mulle-craft log 9

# Just the errors/warnings of the latest run, across all projects:
mulle-craft log errors
mulle-craft log warnings

# Diff the latest run against the previous one (main project):
mulle-craft log diff
```

### Example 7: Cleaning products

```sh
# Remove the kitchen (forces a full rebuild next time).
mulle-craft clean all

# Clean only the installed dependency products.
mulle-craft clean dependency
```

## 7. Dependencies

`mulle-craft` is a router/builder on top of the mulle-sde tool set. Its direct
runtime dependencies (invoked at runtime, not linked) are:

- `mulle-bashfunctions` — provides the shell bootstrap and helper functions
  (`r_*`, `log_*`, `_options_*`, `include`).
- `mulle-make` — performs the actual build/install of each project.
- `mulle-dispense` — installs crafted products into the dependency folder.
- `mulle-sourcetree` — generates the craftorder and is used with the qualifier
  to filter it.
- `mulle-platform` — supplies the system platform (`MULLE_UNAME`).
- `mulle-env` / `mulle-sde` — surrounding environment and IDE shell.
